# EPUB Reader — Phase 0~1

개인용 고성능 EPUB 리더. 원본 파일을 이동/복사하지 않고 그대로 사용하는 서재형 라이브러리.

이번 단계(Phase 0~2)에서 구현된 것:

- EPUB 파일 선택 (원본 위치 그대로, 이동/복사 없음)
- 캐시 디렉토리에 1회만 압축 해제 (`ensureExtracted`가 해시 기반으로 재사용 여부 판단 → 두 번째 열 때부터는 즉시 열림)
- `container.xml → OPF → manifest/spine` 파싱 (EPUB2 우선, EPUB3 폴백)
- EPUB2(NCX) / EPUB3(NAV) 목차 파싱 + 바텀시트 목차 UI
- WebView(`webview_flutter`)로 챕터 XHTML 렌더링 (로컬 CSS/이미지/폰트 상대경로 그대로 로드됨)
- 이전/다음 챕터 이동
- **읽던 위치 저장/복원** (SQLite/drift): 책마다 마지막 챕터 + 그 챕터 안 스크롤 비율을 저장하고,
  다시 열면 자동으로 그 위치로 스크롤 복원. 4초마다 자동 저장 + 챕터 이동 시 즉시 저장 +
  앱이 백그라운드로 갈 때도 저장.
- **라이브러리 목록을 DB에 영구 저장**: 한 번 연 책은 앱을 껐다 켜도 목록에 남아있고,
  목록에서 탭해서 다시 열면 항상 같은 경로로 열려서 읽던 위치가 정확히 이어집니다.
- **제목+작가로 책을 식별**: 파일 경로가 아니라 EPUB의 제목+작가 메타데이터로 "같은 책"을
  인식합니다. 그래서 파일을 다시 선택하거나(새 경로), 오탈자 수정 등으로 파일 내용이
  업데이트되어도 제목/작가가 같으면 같은 책으로 인식되어 읽던 위치가 이어집니다.
  (형광펜/메모/책갈피도 Phase 5~6에서 이 책 식별자에 연결되어 같은 방식으로 유지됩니다.)
- **읽기 설정** (화면 중앙 탭 → 상단 바 → "Aa" 아이콘): 폰트 / 글자 크기 / 좌우 여백 / 줄 간격 /
  문단 간격 / 테마(원본·라이트·다크·사용자 지정 배경색+글자색). 항목마다 "원본 사용" 토글이
  있어서 건드리지 않은 항목은 EPUB 원본 CSS 그대로 표시됩니다. 슬라이더를 움직이면 즉시
  반영되고(0.4초 후 자동 저장), 앱 전체에 공통으로 적용됩니다.
- **페이지 넘김 방식으로 전환** (스크롤 아님): 챕터를 화면 너비 단위의 "페이지"로 나눠서 읽습니다.
  화면 왼쪽 30% 탭 = 이전 페이지, 오른쪽 30% 탭 = 다음 페이지, 가운데 40% 탭 = 상/하단 툴바
  토글. 페이지 끝에서 다음으로 넘기면 자동으로 다음 챕터 첫 페이지로, 챕터 첫 페이지에서
  이전으로 넘기면 자동으로 이전 챕터 마지막 페이지로 이동합니다. 본문 안의 링크(각주 등)는
  페이지 넘김으로 가로채지 않고 그대로 클릭됩니다.
  상/하단 툴바가 숨겨지면 안드로이드 상태표시줄/내비게이션 바도 함께 숨겨져 완전 몰입 모드가 됩니다.
  손가락 드래그로도 자유롭게 넘길 수 있고, 손을 떼면 가까운 페이지 경계로 자동 스냅됩니다.
- **설정이 즉시 반영**: 이전에는 페이지의 이미지/폰트가 다 로드된 뒤에야 우리 설정이 적용돼서
  느린 웹폰트가 있는 챕터에서 몇 초씩 늦게 반영됐습니다. 이제 HTML 구조만 다 읽히면 바로
  적용되는 시점(DOMContentLoaded)에 반영해서 훨씬 빠릅니다.
- **상하 여백 추가**, 읽기 설정 시트를 화면 절반 이하 크기로 줄이고 뒤 배경을 투명하게 해서,
  설정을 조절하면서 바로 아래 페이지가 실시간으로 바뀌는 걸 확인할 수 있습니다.
- **목차 개선**: 자식이 있는 항목은 접기/펼치기 가능(현재 읽는 챕터로 이어지는 경로는 자동으로
  펼쳐진 상태로 시작), 현재 읽는 챕터는 굵게+아이콘으로 표시, 상단 검색창으로 목차 제목 검색.

## 로컬 설치 없이 클라우드에서 APK 빌드하기 (추천)

Flutter SDK를 설치하기 귀찮다면, GitHub Actions가 대신 빌드해줍니다.
`.github/workflows/build-apk.yml`이 이미 포함되어 있습니다.

1. https://github.com 에서 무료 계정 생성 (이미 있으면 생략)
2. 새 저장소(Repository) 생성 (Public/Private 아무거나 상관없음)
3. 이 프로젝트 폴더 전체(이 `epub_reader/`) 내용을 저장소에 업로드
   - git 명령어를 몰라도 GitHub 웹사이트에서 "Add file → Upload files"로 폴더 내용을 드래그 앤 드롭하면 됩니다
4. 업로드가 끝나면(= main 브랜치에 push되면) 저장소 상단 **Actions** 탭에서
   "Build APK" 워크플로가 자동으로 시작됩니다 (5~10분 소요)
5. 완료되면 해당 실행(run) 페이지 하단 **Artifacts** 섹션에서
   `epub-reader-debug-apk`를 다운로드 → 압축을 풀면 `app-debug.apk`
6. `app-debug.apk`를 폰으로 옮겨서 설치
   (안드로이드에서 "출처를 알 수 없는 앱 설치 허용" 필요할 수 있음)

이 방식은 사용자님 PC에 Flutter/Android Studio를 **전혀 설치하지 않고**,
GitHub의 클라우드 서버에서 대신 빌드해주는 방식입니다.
코드를 수정하고 다시 push할 때마다 새 APK가 자동으로 만들어집니다.

## 로컬에서 실행하는 방법 (Flutter SDK가 이미 있는 경우)

이 컨테이너에는 Flutter SDK와 `pub.dev` 접근 권한이 없어서 여기서는 빌드/실행이 불가능합니다.
아래 순서대로 **본인 PC**(Flutter SDK + Android Studio 설치됨)에서 실행하세요.

```bash
# 1. 이 프로젝트 폴더로 이동
cd epub_reader

# 2. Android 플랫폼 폴더(android/, ios/ 등) 생성
#    - 기존 lib/, pubspec.yaml은 건드리지 않습니다.
flutter create .

# 3. 패키지 설치
flutter pub get

# 3-1. DB 코드 생성 (drift) - app_database.dart를 고칠 때마다 다시 실행해야 함
dart run build_runner build --delete-conflicting-outputs

# 4. 실제 기기 또는 에뮬레이터 연결 후 실행
flutter run
```

### 확인해볼 것

1. 앱 실행 → "EPUB 열기" 버튼 → 기기에 있는 `.epub` 파일 선택
2. 책이 열리면 상/하단 툴바 없이 본문만 꽉 차게 보이는지 확인 (기본 몰입 모드)
3. 화면 오른쪽을 탭하면 다음 페이지로, 왼쪽을 탭하면 이전 페이지로 넘어가는지 확인
4. 화면 가운데를 탭하면 상/하단 툴바가 나타나고, 다시 탭하면 사라지는지 확인
5. 챕터 마지막 페이지에서 오른쪽 탭 → 다음 챕터 첫 페이지로 자동 이동하는지 확인
6. 챕터 첫 페이지에서 왼쪽 탭 → 이전 챕터 마지막 페이지로 자동 이동하는지 확인
7. 툴바를 띄운 상태에서 "목차" 아이콘으로 특정 챕터로 점프
8. 같은 책을 다시 열었을 때 압축 해제를 건너뛰고 더 빠르게 열리는지 확인
   (`EpubCacheService`가 파일 크기+수정시각 해시로 캐시 유효성을 판단합니다)
9. 페이지를 넘긴 직후 바로 앱을 꺼도, 다시 열었을 때 그 페이지로 복원되는지 확인
10. 툴바를 띄운 상태에서 "Aa" 아이콘 → 읽기 설정 시트 확인
11. 글자 크기 슬라이더를 움직여서 바로 커지고, 페이지 수(하단 라벨)가 다시 계산되는지 확인
12. 테마를 "다크"로 바꿔서 배경/글자색이 바뀌는지, 뒤로 나갔다 다시 들어와도 유지되는지 확인
13. 폰트/여백/줄간격/문단간격을 각각 켜고 끄면서 "원본 사용" 토글이 정상 작동하는지 확인
14. 본문 안의 각주/링크를 탭했을 때 페이지가 안 넘어가고 링크가 정상 동작하는지 확인

### 테스트용 EPUB이 없다면

Project Gutenberg(https://www.gutenberg.org)에서 EPUB2 형식 공개도서를 받아 테스트하시면 됩니다.
EPUB2/EPUB3 각각 하나씩 테스트해서 목차와 스파인이 정상적으로 파싱되는지 확인해보세요.

## 알려진 제한 사항 (이번 단계 기준)

- **CSS 컬럼 기반 페이지네이션은 완벽하지 않을 수 있습니다.** 이미지나 표가 큰 경우 페이지
  경계에서 살짝 잘리거나, 브라우저 렌더링 엔진의 서브픽셀 반올림 때문에 아주 드물게 한두
  글자가 다음 페이지로 밀리는 경우가 있을 수 있습니다. (Readium/epub.js 같은 다른 EPUB
  뷰어들도 겪는 근본적으로 어려운 문제입니다. Phase 11에서 페이지 넘김 애니메이션과 함께
  다듬을 예정입니다.)
- 페이지 수는 "챕터 안에서의 페이지"만 계산합니다. 책 전체 기준 페이지 번호/퍼센트 표시는
  아직 없습니다 (Phase 7 검색, Phase 11 성능 작업과 함께 고려 예정).
- **제목+작가가 완전히 같은 서로 다른 책은 같은 책으로 오인식됩니다** (예: 같은 제목의 서로 다른
  단편선). 이런 경우가 실제로 문제가 되면 이후에 "파일 크기가 크게 다르면 다른 책으로 취급"
  같은 보조 규칙을 추가할 수 있습니다.
- **`file_picker`는 Android에서 원본 파일을 앱 캐시 폴더로 복사한 뒤 그 경로를 돌려줍니다.**
  이 복사본 경로로 책을 식별하기 때문에, 라이브러리 목록에서 탭해서 여는 한 계속 같은 책으로
  인식되지만, OS가 앱 캐시를 강제로 비우면(저장공간 부족 등) 그 복사본이 사라져서 "파일을 찾을
  수 없음" 상태가 될 수 있습니다. 이 경우 목록에서 지우고 "EPUB 열기"로 다시 선택해야 합니다.
  Phase 8에서 SAF(Storage Access Framework)의 영구 권한(persistable URI permission) 방식으로
  전환하면 이 제약이 사라지고, 요구사항대로 진짜 원본 위치를 그대로 참조하게 됩니다.
- 표지 판별 로직이 단순합니다 (EPUB3 `properties="cover-image"` 속성을 아직 직접 읽지 않고 파일명 휴리스틱 사용). Phase 8(라이브러리) 작업 때 정식으로 고칠 예정입니다.
- `<meta name="cover">` / `<dc:title>` 등 네임스페이스 처리를 단순화했습니다. 실제 다양한 EPUB로 테스트하며 예외 케이스를 계속 보강해야 합니다.
- WebView 하나로 매 챕터를 새로 로드합니다. 챕터 전환 애니메이션과 프리로딩(다음 챕터 미리 불러두기)은 Phase 11에서 최적화합니다.
